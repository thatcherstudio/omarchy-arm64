## Objective

Make build and verification repeatable on GitHub-hosted native runners, with isolated architectures and controlled publication.

## Files

.github/workflows/nightly-build.yml; workflow_dispatch build workflow; docs/ci.md

## Steps

1. Use x86 ubuntu-latest (record resolved image) and ubuntu-24.04-arm with arch matrix; pass --arch and locked source/package inputs.
2. Keep caches, offline DBs, work dirs and artifacts separated by arch/channel; record free disk/RAM preflight and tool/image versions.
3. Run existing upstream checks and new focused tests before builds; upload ISO, checksum, package manifest and diagnostic logs per arch, including on failure.
4. Use explicit read-only default permissions; signing/publication remains in #8 workflow. Enable scheduling only after manual matrix qualification.
5. Document fork PR limits, runner disk budget, timeouts and QEMU smoke acceleration fallback.

## Acceptance criteria

- [ ] Workflow validates and a manual run records real native aarch64 on the ARM leg.
- [ ] Both build/test legs pass before enabling nightly; failed runs retain diagnostics.
- [ ] Per-arch artifacts cannot overwrite each other and no upstream release credentials are used.
