## Objective

Separate UTM success from the generic UEFI ARM claim. Target one available physical UEFI/ACPI ARM system or a documented additional virtual platform.

## Files

docs/evidence/validation/generic-uefi.md; docs/hardware-support.md

## Steps

1. Choose an available target and record firmware, boot media, ACPI/device support and exact artifact hash; do not assume a cloud VM can boot an optical ISO.
2. Test the same install, encrypted boot, networking, kernel update and recovery contract.
3. Record device-specific failures and scope supported hardware to evidence. Bare-metal Apple Silicon and SBC/U-Boot stay out of scope.
4. If no additional target is available, leave hardware qualification open. A UTM-only release decision requires an explicit documented scope change, not a fabricated PASS.

## Acceptance criteria

- [ ] At least one additional target has an honest result with reproducible procedure.
- [ ] A passed target has installed boot/update evidence; unsupported devices are named.
- [ ] No broad generic-hardware certification based only on QEMU/UTM.
