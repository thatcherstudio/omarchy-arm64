## Objective

Make the selected complete package set pacman-consumable with a project GPG key, reproducible provenance and rollback. This remains necessary even when upstream/community bytes are reused.

## Files

packages/keyring/ (public material only); .github/workflows/publish-packages.yml; scripts/verify-package-repo.sh; docs/package-repository.md; docs/evidence/packages/publication.json

## Steps

1. Use GitHub Release assets in this repo at an immutable versioned tag; publish a literal repository URL and DB name. Check redistribution rights and reuse audited bytes where allowed.
2. Establish project key custody and CI signing subkey, public fingerprint/bootstrap instructions and rotation/rollback policy. Never commit private keys.
3. Sign packages and database, upload a complete snapshot, verify it publicly before selecting it for clients. Require PackageRequired DatabaseRequired TrustedOnly for the project feed.
4. In a clean aarch64 chroot populate ALARM + project keyrings, sync, resolve and install the required closure. Retain hashes and test rejection of tampered artifacts/untrusted signatures.
5. Keep mutable alias promotion separate from immutable publication; a DB/signature mismatch must fail closed. Record verified package sources.

## Acceptance criteria

- [ ] Exact DB/package/signature URLs return 200; all advertised assets match hashes and trusted signatures.
- [ ] pacman sync and full closure installation succeed in a fresh ARM environment.
- [ ] Unsigned/tampered fixture is rejected; prior signed snapshot remains retrievable.
