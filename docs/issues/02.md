## Objective

Finalize the implementation inputs for ADR 001. ALARM is the distribution; its rootfs is a bootstrap option. Preserve the accepted reuse-first direction.

## Files

docs/adr/001-base-distro.md; docs/evidence/base-qualification.md; docs/sources.lock.json

## Steps

1. Verify an aarch64 builder image or rootfs, pin digest/checksum and document keyring bootstrap; do not trust the example Docker image names without manifest checks.
2. Verify linux-aarch64, matching headers, /boot/Image and initramfs/preset files against an ALARM package. Record supported repo names and transport.
3. Resolve the observed HTTPS hostname failures using maintained mirror configuration; never disable TLS verification or ALARM package signatures.
4. Choose an explicit runtime/settings source pair; document project-signed GitHub Release snapshots and reject wholesale Asahi desktop replacement.

## Acceptance criteria

- [ ] ADR records image/rootfs pin, source pin, kernel files, mirror policy and exact package lane.
- [ ] Kernel/header metadata comes from a real ARM environment; evidence includes command output.
- [ ] The fast path uses existing compatible official-edge/community artifacts; rebuild criteria and generic UEFI scope are explicit.
